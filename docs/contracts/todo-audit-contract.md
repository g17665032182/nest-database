# TODO 用户隔离与操作日志契约

## 契约状态

- 状态：已确认
- 资源名称：TODO 用户隔离与操作日志
- 需求来源：用户要求实现 TODO 操作日志，并同意先做用户数据隔离、操作日志和历史查询
- 确认依据：用户需求、用户回复、现有项目约定
- 涉及模块：todos、todo-logs、auth、users
- 当前技术栈及版本：NestJS 11、MikroORM 7.1.8、PostgreSQL、Fastify、pnpm
- 最后更新：2026-10-26

## 需求范围

- 业务目的：用户只能访问自己的 TODO，并能查看自己发起的 TODO 操作记录。
- 包含的操作：现有 TODO 创建、列表、详情、更新、删除；操作历史查询。
- 明确不包含：软删除与恢复、操作回滚、读取行为审计、历史记录清理任务。
- 已阅读的相似模块及约定：`src/todos`、`src/auth`、`src/users`；仓库全局 JWT Guard 和 DTO ValidationPipe。

## API 契约

| 操作 | 方法与路由 | 请求 DTO/参数 | 响应形状 | 认证/授权 | 状态码与错误行为 |
| ---- | ---------- | ------------- | -------- | --------- | ---------------- |
| TODO 创建 | `POST /todos` | 现有 `CreateTodoDto` | TODO | JWT；所有者由服务端设置 | 沿用现有行为 |
| TODO 列表 | `GET /todos` | 现有分页 DTO | 当前用户的 TODO 列表 | JWT；仅所有者 | 仅返回当前用户数据 |
| TODO 详情 | `GET /todos/:id` | 路径参数 | TODO | JWT；仅所有者 | 非本人或不存在统一返回 404 |
| TODO 更新 | `PATCH /todos/:id` | 现有 `UpdateTodoDto` | TODO | JWT；仅所有者 | 成功写入时同时写日志 |
| TODO 删除 | `DELETE /todos/:id` | 路径参数 | 删除结果 | JWT；仅所有者 | 物理删除；成功时保留日志 |
| 我的操作历史 | `GET /todos/history` | 分页、可选操作类型和 TODO ID 筛选 | `{ items, total, page, limit }` | JWT；仅当前用户 | 默认按操作时间倒序 |

## 查询、权限与删除规则

- 分页方式及默认/最大页大小：建议 `page=1`、`limit=20`、最大 `100`，待确认。
- 排序字段与默认排序：操作时间倒序，不接受客户端指定排序字段。
- 过滤条件：建议支持操作类型和 TODO ID，待确认。
- 是否公开；认证方式：不公开；复用全局 JWT Guard。
- 角色或资源所有权规则：TODO 所有者从已验证 JWT 的 `sub` 获取；所有 CRUD 查询必须限定所有者；请求体不得设置所有者或操作者。
- 删除方式：TODO 维持现有物理删除；操作日志只追加，不提供更新/删除接口。
- 被关联记录的处理方式：建议操作日志在 TODO 物理删除后继续保留；日志记录中的 TODO ID 使用普通整数而非级联外键，待确认。
- 并发更新或事务要求：TODO 变更与日志写入在同一数据库事务中；失败时两者都不提交。
- 旧数据处理：迁移不得猜测 TODO 所有者；建议保留旧记录并令其所有者为空，所有用户 API 均不可见这些未归属记录，待确认。
- 用户删除行为：当前没有用户删除 API；日志操作者外键使用 restrict，保留日志完整性并阻止删除仍有历史记录的用户。
- 错误响应：其他用户的 TODO 与不存在的 TODO 均返回 404，避免资源枚举。
- 迁移兼容性：需保留现有数据；禁止清库或运行 `orm:fresh`。
